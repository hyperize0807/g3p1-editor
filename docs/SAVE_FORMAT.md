## 1. 난독화 (XOR 0xFF)

파일 전체가 바이트마다 `^0xFF` 되어 디스크에 저장됨.
- **디코드**: 모든 바이트 `^0xFF`
- **인코드**: 동일하게 `^0xFF` (대칭)

디코드하면 0x00이 압도적으로 많은 정상 구조가 드러남.

## 2. 변조방지 체크섬 (★중요)

게임은 로드 시 체크섬을 검증하고, 불일치하면
`"세이브 파일에 오류가 생겼거나 허가없이 변경되었습니다. 로드할 수 없습니다."` 표시 후 로드 거부.

- 역분석 출처: `alpha.dll` 검증 함수 `@0x100A7D90`, 기록 함수 `@0x100A7E30`.
- **계산 대상은 RAW(디스크/XOR된) 바이트**, 마지막 2바이트(체크섬 자신) 제외.

```
acc = 0
for i in 0 .. (파일길이-3):                 # 마지막 2바이트 제외
    acc = (acc + rawByte[i] * (2*(i & 3) + 1)) % 32000   # 가중치 1,3,5,7 반복
# acc(0..31999)를 파일 끝 2바이트에 LE로 기록:
file[len-2] = acc & 0xFF
file[len-1] = (acc >> 8) & 0xFF
```

검증: G30002/3/4 + 게임이 만든 mod 모두 계산값=저장값 일치. 에디터는 저장 시 이 값을 재계산하여 게임이 정상 로드함(무편집 저장 시 원본과 바이트 동일 확인).

### 2.1 버전별 가중치 (★1.03+ vs 1.04)

세이브 포맷은 **1.03+와 1.04가 우리가 다루는 모든 필드에서 바이트 단위로 동일**하며, **유일한 차이가 이 체크섬 가중치**다.

| 버전 | 가중치 식 | 가중치 주기 |
|---|---|---|
| **1.03+** | `2*(i&3)+1` | 1,3,5,7 |
| **1.04** | `2*(i&3)+3` | 3,5,7,9 |

- 모듈러스(32000)·계산범위(끝 2바이트 제외)·저장 위치(LE)는 동일.
- 1.04 샘플(연대표 4개 + 진행 세이브 G30005 시반/G30007 아포)로 검증: 가중치 3,5,7,9에서만 저장 체크섬과 일치.
- **버전 자동판별**: 저장된 체크섬에 base=1을 넣어 맞으면 1.03+, base=3이 맞으면 1.04. 둘 다 아니면 **알 수 없는 버전 → 로드 거부**(에디터는 편집 차단).
- **데이터 레이아웃 동일성 검증(1.04)**: XOR 0xFF, 마커 `30 3A 10 10` @0x40c, 340B 레코드/갭, 캐릭터 내부 필드(charId@0x44=196 살라딘, group/job/장비@0x82../어빌@0x8C), 소지금 0x13B58 슬롯 매핑(ep0→slot0=81345, ep2→slot3=31025, slot2=131459 상수 예비), 보관함 시그니처 스캔(G30005 28종/G30007 8종 사용자 데이터와 정확히 일치) — 전부 1.03+와 동일하게 동작. slot2 상수값만 1.03+(470279)과 다름(편집 무관).

### 2.2 에디터의 버전 처리
- 로드: `detectVersion(raw)`로 자동판별 → 헤더에 "감지: 1.04 버전" 배지 + 저장 버전 셀렉터를 감지값으로 설정. 미지원 패턴이면 로드 거부(편집 UI 비표시, 저장/보관함 버튼 비활성, 안내 + "다른 .sav 열기" 버튼).
- 저장: 헤더 **저장 버전 셀렉터**(1.03+/1.04)의 가중치로 체크섬 재계산. 기본은 로드한 버전(버전 보존). 로드 버전과 다르게 고르면 "⚠ 다른 버전으로 저장합니다" 경고 표시(교차 변환 허용 — 단 게임 본체 콘텐츠 차이로 인한 호환성은 보장 못함).
- 라운드트립 검증: 1.03+/1.04 모두 무편집 저장 시 원본과 **바이트 완전 동일**(Preview에서 실제 샘플로 확인).

## 3. 파일 거시 구조 (318레코드 표준 세이브 기준)

세이브는 **3개 에피소드 스냅샷 섹션**으로 구성. 각 캐릭터 블록 사이의 "갭"에 소지금/보관함/플래그 등이 들어감.

```
0x000          헤더 (0x00 = 현재 에피소드, 0x04 = 챕터 추정)
0x40C  ┐
       │  블록0: 캐릭터 레코드 106개 (각 340B)  → 0x90D4
GAP0   │  (≈0x90D4 ~ 0x196B0) : 소지금(0x13B58) + 보관함들 + 플래그 + 게임기본목록
0x196B0│  블록1: 캐릭터 레코드 106개            → 0x22378
GAP1   │  (0x22378 ~ 0x2E4D0)
0x2E4D0│  블록2: 캐릭터 레코드 106개            → 0x37198
TAIL   ┘  (0x37198 ~ EOF) : 마커 74391010 영역(파티 인덱스 등) + 끝2B 체크섬
```

- 총 318 레코드 = **106 캐릭터 × 3블록**(에피소드 스냅샷). 세 블록은 동일한 (charId,이름) 시퀀스(같은 로스터, 같은 순서), 값만 약간 다름. 연대표(212레코드)는 2블록, 즉 **블록크기(주기)=106 고정**, 블록 수만 다름.
- ※ charId는 고유 키가 아님(범용 유닛이 charId 공유, 일부는 이름까지 다름) → 중복 제거/일괄적용은 **위치(슬롯) 기반**으로 해야 정확. 슬롯 i의 모든 블록 = 인덱스 i, i+106, i+212…. 에디터는 (charId,이름) 시퀀스가 반복되는 최소 주기 P를 탐지해 사용.
- 레코드는 마커 `30 3A 10 10`(LE u32 = 0x10103A30)로 시작. 파싱은 마커 스캔으로 안전하게 가능.
- **블록 사이엔 갭이 있어 레코드가 연속 배치는 아님** → 마커를 스캔해 각 340B를 읽을 것.
- 연대표 세이브(G30001/G30006)는 212 레코드(2블록) 등 더 작을 수 있으나 소지금은 동일하게 0x13B58.

> 능력치(STR~WTP)는 **각 1바이트(0~255)**. HP/EXP만 u32.

### 4.1 어빌리티 배열 (+0x8C, 200바이트)
- `record[+0x8C + 어빌리티ID]` = 레벨. **0xFF = 미보유**(SaveEdit는 0으로 표시), **1 이상 = 보유 레벨**. (00 값은 관측되지 않음 — 미보유는 항상 0xFF)
- 인덱스 = Abil.txt ID. 예: id1~9=HP/STR/SKILL/DEX/INT/RANGE/SPD/AC/MR 랭크, **id23~31=연계기(연·살·비·혼·파·초·참·격·광, 0~5)**, id10~22=장비 숙련, id32+=마법/스킬.
- 검증: 살라딘 연(23)=5, 쌍검술(128)=7 등 24개 보유. `alpha.dll @0x1009D500`이 0xFF로 초기화 후 채우는 코드로 확인.
- 편집: 레벨 0 입력 → 0xFF(미보유) 기록, 1+ → 레벨 기록. Abil.txt에 없는 id(93,96,102 등)도 보유 시 그대로 표시/편집 가능.
- ※ 이전에 +0x6A(전부 10)를 연계기로 오판했었음 → 실제 연계기는 이 배열의 id23~31.

### 4.2 어빌리티 최대 레벨 (경계값) — `dats\Abi.dat`
- **Abi.dat = XOR 0xFF 난독화**, 39바이트 고정 레코드. `record(id) = (id-1)*39`, 이름은 record+2(CP949).
- **record+0x20 (raw 바이트) = 해당 어빌리티의 최대 레벨**. (검증: 장비=1, 연계기=5와 일치. 카테고리 내에서도 값이 달라 — SPD=4, 초(28)=1 — 단순 카테고리가 아닌 per-ability 최대값.)
- 추출 결과 분포(160개): 1(97), 5(35), 3(14), 9(8), 7(4), 4(1), 2(1).
  - 스탯(1~9) = **9** (단 SPD=4) — ※게임 내 사용자 관측은 7이었으나 **데이터값은 9**. 게임이 7로 추가 제한하는지 미확인.
  - 장비(10~22) = 1, 연계기(23~31) = 5(단 초28=1).
- 추출물: `abil_max.json`(에디터 내장), `abil_max.txt`(가독 목록). 생성: `abimax2.py`(직접 공식). 에디터는 어빌리티별 입력 상한 + "(최대 N)" 표시 + 초과 입력 자동 클램프.
- id 178~181은 Abi.dat 레코드 없음(177개) → 에디터 기본 최대 9.

## 5. 에피소드 지시자 (0x00)

파일 오프셋 `0x00`의 u32 = **현재 진행 에피소드 인덱스**.

| 값 | 의미 |
|---|---|
| 0 | 시반슈미터 |
| 1 | 크림슨크루세이더 |
| 2 | 아포칼립스 |
| 0xFFFFFFFF (-1) | 연대표 (진행 중 에피소드 없음) |

(0x04 = 챕터 번호 추정. 연대표 세이브는 0x04도 0xFFFFFFFF.)

## 6. 소지금 (소지금)

`0x13B58`부터 **u32 × 4** (모든 세이브에서 고정 오프셋, 212레코드 세이브 포함).

| 슬롯 | 오프셋 | 에피소드 | 근거 |
|---|---|---|---|
| 0 | 0x13B58 | 시반슈미터 (ep0) | G30002 표시값 862096 일치 |
| 1 | 0x13B5C | 크림슨크루세이더 (ep1) | G30003 표시값 388463 일치 |
| 2 | 0x13B60 | **비표시 예비 슬롯(미확정)** | 5개 세이브 전부 470279 상수, 표시값과 불일치 |
| 3 | 0x13B64 | 아포칼립스 (ep2) | G30004 표시값 11580 일치 |

- **에피소드→슬롯 매핑: ep0→0, ep1→1, ep2→3** (정답값 검증).
- **사용자가 보는 소지금 = slot[현재에피소드]**.
- slot2(0x13B60)는 표시 소지금과 한 번도 안 맞는 비표시 슬롯. 코드에 하드코딩 기본값도 아님(실데이터). 정체 미확정 — 아포가 잃은 아이템/돈을 되찾는 시점 세이브가 있으면 규명 가능.

## 7. 보관함 (아이템 저장소)

### 구조
연속된 테이블: **`[개수: u32] [ (아이템ID: u32, 수량: u32) × 개수 ]`** 그 뒤 빈/잔여 공간.
- 통제 실험(G30004 vs mod, G30002 vs test)으로 검증.
- 게임은 보관함 확장 시 **제자리에서** 배열 뒤 영역(0 또는 과거 잔여 데이터)을 덮어쓰며 개수를 늘림(파일 크기 불변).

### 탐지 (오프셋 고정 아님 → 스캔)
보관함 절대 오프셋은 진행도에 따라 이동하므로 시그니처 스캔으로 탐지:
- **2바이트 정렬**로 스캔 (테이블이 2바이트 경계에 올 수 있음)
- 조건: 개수 2~120, 직전 u32 == 0, 모든 쌍이 (1≤id≤181, 1≤qty≤999)
- 종료자 검사 없음(테이블이 연속 배치됨), 매칭 시 테이블 끝으로 점프
- **순서 무관(멀티셋)으로 그룹핑** → 3개 스냅샷 섹션의 동일 사본을 묶어 함께 편집(라이브 사본 포함 → 게임 반영)
- 빈 슬롯(추가 가능 수) = 배열 뒤 "다음 실제 구조" 전까지의 쌍 수 (id≤181 & qty≤999인 잔여/0 영역, 다음 구조에서 중단)

### 에피소드 라벨링 규칙
- **현재 에피소드 보관함(확정)** = 0x00이 유효(0~2)하고, minOff가 (0x13B58, 블록1마커) 사이(소지금 뒤 작업영역)인 그룹. 게임에서 실제 접근하는 라이브 보관함.
- **다른 에피소드(추정)** = 소지금 앞(minOff < 0x13B58) 비정적 그룹을 오프셋 순으로 비현재 에피소드 인덱스 [0,1,2]\{현재}에 순서대로 매핑.
- 연대표 세이브(0x00=-1)는 "현재" 보관함 없음 → 전부 위험 영역.

### 게임 기본 아이템 목록 (보관함 아님)
- 61종, 모든 세이브에서 **바이트까지 동일**한 정적 게임 데이터. 보관함이 아님 → 편집 금지/제외.
- 멀티셋 시그니처(`STATIC_SIG`, build_editor.py에 하드코딩)로 식별.

### 8.1 아이템 상세 — `dats\Item.dat` (이름/설명/공격스탯)
- **텍스트는 XOR 0xFF, 숫자는 평문(raw)** (Abi.dat과 동일 패턴). **204바이트 고정 레코드, 181개**. `record(id) = (id-1)*204` (id 1=단검; id 0=없음은 레코드 없음).
- 레코드 내 고정 필드:
  - [텍스트, XOR 디코드] `+0x02` 한글 이름(CP949) · `+0x20` 영문 이름(ASCII) · **`+0x6A` 한글 설명(CP949, null 종료)**
  - [숫자, raw 평문] **`+0x50` TS**(단일 공격력) · **`+0x69` SS**(연속기 공격력) — **물리 무기만 >0**(써크렛/방어구/소비는 0). 게임 내 무기 툴팁의 TS/SS와 일치(검증: 샤벨 22/100, 실버소드 60/70, 크리샤오르SE 85/80, 기관단총 40/50).
- 설명 예: 회복약 "회복약 (HP+300)", 용아 "힘을 상승시켜 준다. (STR+20)". 방어구/소비는 설명 괄호에 효과 포함. 181개 중 171개 설명 보유, 무기(TS/SS) 107개.
- **분류(cat)**: Item.txt id 구간 기반(게임 고정) — 무기(1~69,144~181)/써크렛(70~75)/방어구(76~96)/장신구(97~125)/소비(126~143)/기타.
- 추출: `tools/gen_itemdat.py` → `tools/item_info.json` (id→{eng,cat,desc?,ts?,ss?}; **이름은 tables.json=tools/G3Data/Item.txt 사용** → 오타수정 단일소스). 에디터 사전/툴팁에 사용.
- 참고: G3Data 오타/오표기는 tools/G3Data에서 수정 — Item: 자마드 아그니, 킬링 필드 / **Abil #151 `쌍권총 연사` → `필살 6연사`(게임 내 표기 일치)**. 게임쪽 원본은 미수정이며 빌드는 tools/G3Data 사용.

### 8.2 직업/전직 데이터 — 나무위키 「창세기전 3/직업」
- 게임 세이브/데이터 파일에는 **전직 조건이 노출되지 않음**(상위 직업으로 가려면 어떤 어빌을 얼마나 익혀야 하는지 게임 내 확인 불가) → 커뮤니티 정리 문서(나무위키)를 사전화.
- 출처: namu.wiki `창세기전 3/직업` (CC BY-NC-SA 2.0 KR). namu.wiki는 봇 접근 차단 → **저장된 HTML**(`samples/job/*.html`, git 제외)에서 추출.
- 파이프라인: `job_extract.py`(HTML→`extracted.txt` 텍스트) → `gen_jobs.py`(파싱→`jobs.json` + `tables.json`으로 Job/Abil ID 매핑).
- 파싱 규칙: 대제목=나라(투르/팬드래건 왕국/게이시르 제국/한 제국; `5. 기타 계열`부터 버림) / 부제목=세력 / `직업명 : 전직조건어빌…`(콜론) / `ㄴ습득어빌…`. 어빌 토큰은 **앞 숫자=최대레벨, 괄호 `(n)`=최단루트 최소레벨**. 그룹라벨(칼리프측 등)·각주·서술팁은 제외, 가이드(시반 슈미터·왕국 기사단 최단루트)만 세력 단위 보존.

## 9. 에디터 구현 (index.html)

- **빌드**: `python tools/build_editor.py` → `dist/index.html` 생성 (`tools/tables.json` + `abil_max.json` + `item_info.json` 내장).
- 단일 HTML 파일, 브라우저에서 로컬 처리(업로드 없음).
- 기능:
  - .sav 열기 → XOR 디코드 → 마커 스캔으로 318 레코드 파싱(이름 = TextDecoder('euc-kr'))
  - **캐릭터 목록**: 블록 주기(106)로 **중복 제거 → 캐릭터당 1개**만 표시(`·×N` 배지=적용 블록 수). 검색도 1개만 매칭.
  - **캐릭터 편집**: 이름(읽기전용)/ID/소속/직업/초상화, 능력치(HP,EXP,STR~WTP), 장비 5슬롯, **어빌리티(보유목록 레벨편집+추가/제거+어빌리티별 최대레벨 클램프, +0x8C 배열)**, 고급(전체 u16 그리드+HEX). "모든 에피소드 블록에 적용" 옵션(기본 ON, **위치/슬롯 기반** = 인덱스 i,i+106,i+212…).
  - **소지금**: 현재 에피소드 표시값만 전면, 나머지는 "기타 소지금 ⚠️" 펼치기.
  - **보관함**: 현재 에피소드 = ✅ 안전 편집 영역, 그 외 = ⚠️ 위험 영역(접힘, 펼쳐야 접근, 경고문). 아이템 추가/삭제/종류·수량 변경.
  - **아이템 사전(📖)**: `ITEM_INFO`(Item.dat 추출) 기반 검색(이름/영문/설명/번호) + 분류 필터 + 무기 TS/SS.
  - **직업 사전(📜)**: `JOBS`(jobs.json) 기반 나라·세력별 직업 트리(전직조건/습득어빌·최대레벨) + 검색 + 나라 필터 + 최단루트 가이드(시반블레이드/성기사단). 어빌명은 abilId 있으면 `TABLES.Abil` 정식명으로 표시. §8.2.
  - **아이템 드롭다운(커스텀)**: 장비·보관함의 아이템 선택은 네이티브 `<select>` 대신 **커스텀 드롭다운**(`itemSelHtml`/`itemField`/`pickItem`). 네이티브 option은 부분 스타일이 불가하므로, 행마다 **이름 굵게+강조색(`.in`)** + TS/SS(`.iw`) + 설명(`.im`)을 표시하고 검색 가능. 메뉴는 `position:fixed`로 좌표 계산(스크롤 컨테이너 클리핑 회피), **바깥** 스크롤/리사이즈/바깥클릭 시 닫힘(메뉴 내부 스크롤은 유지 — scroll 핸들러가 `e.target.closest('.isel-menu')`면 무시; 열 때 `focus({preventScroll:true})`). 컨텍스트는 `data-ioff`(장비) 또는 `data-ginv/data-rinv`(보관함). 선택 시 장비=editTargets에 u16 기록, 보관함=writeGroup.
  - **버전(1.03+/1.04)**: 로드 시 `detectVersion`으로 자동판별·표기, 미지원 패턴은 로드 거부(§2.1/§2.2). 저장 버전 셀렉터로 출력 버전 선택(기본=로드 버전).
  - **저장**: XOR 재인코딩 + **선택 버전 가중치로 체크섬 재계산** → `..._edited.sav` 다운로드.
- 핵심 상수: `VERSIONS`(버전→가중치 base), `GOLD`(슬롯/에피소드 매핑), `EPISODES`, `STATIC_SIG`, `ITEM_INFO`(아이템 사전), 레코드 필드 오프셋 `F{}`.

```python
def load(p): return bytes(b ^ 0xFF for b in open(p,'rb').read())   # 디코드
import struct
u32=lambda b,o: struct.unpack_from('<I',b,o)[0]
MARK=bytes([0x30,0x3A,0x10,0x10]); REC=0x154
def records(b):
    r=[]; i=b.find(MARK)
    while i!=-1 and i+REC<=len(b): r.append(i); i=b.find(MARK,i+1)
    return r
def checksum(raw, base=1):   # raw=디스크 바이트(XOR 안 푼 상태). base=1(1.03+) / 3(1.04)
    acc=0
    for i in range(len(raw)-2): acc=(acc+raw[i]*(2*(i&3)+base))%32000
    return acc
def detect_version(raw):     # 끝 2바이트 LE와 비교
    s=raw[-2]|(raw[-1]<<8)
    return '1.03+' if checksum(raw,1)==s else '1.04' if checksum(raw,3)==s else None
```
